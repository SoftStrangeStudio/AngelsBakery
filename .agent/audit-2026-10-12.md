## Accessibility landmark review — 2026-10-12

- Axe first found `.announcement` outside landmarks. The app shell now wraps announcement and masthead in one semantic banner; the inner masthead keeps its existing `.header` class styling.
- After transitions settled, axe-core WCAG 2.0/2.1 A/AA and best-practice scans returned zero violations on home, menu, product, About, Pickup, FAQ, Contact, empty order, review and confirmation.
- A 390×844 reduced-motion check reported 0s scenic/carousel motion, verified Next changed Snickerdoodles to Sugar Cookies, and kept document width at 390px. Reset the preference and restored the homepage at 1280×720.
- This is automated coverage only; keyboard, screen-reader and complete WCAG review remain distinct from these route scans. `npm run check` passed after the markup change.

## Interactive accessibility states — 2026-10-12

- Replaced the menu product grid’s broad live region with a screen-reader-only `role=status` count/message, avoiding full product-card announcements. Verified 7, 2 and 0-result states and the reset path; axe returned zero violations on each state.
- Native FAQ disclosure opens by Space. In the pastry viewer, focus starts on the Close button, Escape closes the dialog, and focus returns to the selected pastry. The open FAQ and dialog also had zero axe violations.
- The 390×844 no-results capture is `output/soft-strange-bakery-menu-no-results-mobile-390x844.png`; document width matched 390px. `npm run check` passed after the code change. The temporary axe server was stopped.

## Strengths

- Copy, bake-sale schedule, routes, `/AngelsBakery/` base path, reduced-motion support, and preview/order safety gates remain intact.
- The menu now exposes more product photography in a short desktop window without shrinking the homepage hero.
- Product details disclose pending pricing, ingredient/allergen uncertainty, and editorial imagery.
- Mobile checkout stays within 390 CSS pixels. Personal fields were entered only as made-up test data and are not persisted; only the sanitized product ID/quantity is stored.
- At 320 CSS pixels, home, menu, empty-order and preview-review states have no horizontal overflow. The narrow preview action wraps to two lines and stays inside its card.
- The preview action remains on the review page and clearly states that no order or payment was sent.

## Accessibility and usability notes

- The updated preview confirmation is an informational `role=status`, not an error alert.
- Existing skip link, labeled filters/search, pickup radio names, keyboard/reduced-motion behaviors were not changed by this visual follow-up.
- This was not a full WCAG audit; no screen reader hardware session, comprehensive contrast measurement, or real-phone test was performed.

## Validation and limits

- `npm run check` passed after the implementation: lint, typecheck, 19 existing tests, static build/export checks for 20 HTML files, and 18 image decodes.
- A short-phone-specific pass reduces the home hero/carousel from 270px/118px to 220px/98px at ≤700px height. The regular 390×844 phone remains 304px/118px; the 1280×720 menu rule is unaffected.
- Rechecked all 17 current customer routes and reduced motion at 375×667. Routes return 200 with required metadata and base-prefixed assets; zero-duration transitions and immediate scrolling coexist with usable Next navigation.
- Browser console: 0 errors, 0 warnings. At 390×844, document width matched the viewport. The preview-only run generated no Google Apps Script or `/exec` request, no receipt, and no payment. Cart and session storage were cleared afterward.
- Review is local evidence only. Source delivery, commercial hosting, approved business details, deployed-route validation and real-order acceptance remain open in `docs/task-tracker.md`.
